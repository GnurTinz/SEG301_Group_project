# Implementation decisions

1. Keep the specified stack. Initial implementation was local; the user subsequently requested Vercel frontend/Render API deployment preparation and GitHub updates. Hosting configuration preserves the existing runtime.
2. Use npm workspaces. PowerShell commands use npm.cmd where npm.ps1 is blocked.
3. PostgreSQL is mandatory in development and tests. A local ephemeral PostgreSQL helper may replace unavailable Docker infrastructure, never the database technology.
4. Guest search/click logging also uses CSRF-protected anonymous sessions. Store result IDs in search metadata to validate actual result membership and position; never trust client query text.
5. Count one detail view per browser/session/document per 30 minutes. Maintain view event and counter atomically.
6. Moderator edits use dedicated status endpoints; comment text edits remain owner-only.
7. Protect the SUPER_ADMIN role's core permission set and serialize administrator changes in a database transaction to prevent concurrent last-admin removal.
8. Seed articles are original educational explanations, not invented current news. Use local original cover illustrations and environment-provided demo passwords.
9. Pin Prisma to patched 6.19.3 to retain the specified Prisma schema/client workflow; override vulnerable transitive deepmerge-ts/minimatch to patched releases and verify migrations, generation, lint, build and integration tests. Use Zod 4 with the matching maintained resolver. No forced framework migration.
10. View deduplication uses aligned UTC 30-minute buckets, enforced by a unique database key; two requests straddling a bucket boundary may both count. This is a documented approximation, not a rolling window.
11. SUPER_ADMIN always retains its five core administrative permissions, a stricter invariant than protecting only the last administrator. All user status/role/permission mutations take the same transaction-scoped PostgreSQL advisory lock.
12. Seeds preserve existing article content, password hashes, user role assignments and role permission edits. New identities/roles receive defaults inside a transaction. A failed browser verification initially left a test role grant behind; browser tests now await restoration and the fresh verification repeats API RBAC tests afterwards.
13. Test runners create only databases with validated simple names ending in `_test`, never reset/drop existing databases, and use a separate connection from development. The fresh verification database is retained for inspection.
14. Public settings expose only the magazine name and comments-enabled flag. Retention cleanup is an operator command with dry-run default; it is not automatically scheduled. View counters are lifetime totals and remain after old view events are pruned.
15. Vercel proxies API/uploads/health to Render using static destinations in `vercel.json`, targeting the user's supplied `https://seg301-group-project.onrender.com` origin. This supersedes dynamic `vercel.ts`/`RENDER_API_ORIGIN`, rejected by the actual New Project import with a missing-destination error. The former file is retained as a non-active `.ts.example` reference. Browser requests remain same-origin, preserving HttpOnly/Secure/SameSite=Lax sessions and exact-origin CSRF checks. Do not enable third-party cookies or wildcard preview origins. Static frontend builds are independent of Prisma/database configuration.
16. Render binds to `0.0.0.0` and its injected PORT. Proxy trust is an explicit bounded hop count (`TRUST_PROXY=1` for Render, zero locally). All API responses are no-store so CDN caching cannot suppress search/view events or share private responses. Database readiness is separate from process liveness.
17. The Render blueprint defaults to a free API service and an operator-provided database; it provisions no paid database/disk. Migrate and idempotent seed run before startup for single-instance coursework hosting. Durable uploads require an explicitly provisioned persistent disk or future object storage adapter; free filesystem uploads remain temporary. Multi-instance hosting needs a separate release job and shared rate limiting.
18. Root/API `predev` uses `scripts/prepare-dev.mjs`: check required ports before any generation, then reuse the generated client when schema, package version and native engine are present and current. Compare schema without formatting/comments while retaining all quoted values because Prisma formats generated schema. Generate only when needed. This supersedes unconditional generation, which failed on Windows when an existing API held the engine DLL. Vite uses strict port 5173 to match the local CSRF origin. Preparation does not change database data or run migrations/seed; Vercel's frontend-only install/build remains independent of Prisma.
19. Anchor runtime upload ignores to `/uploads/` and `/apps/api/uploads/`. The source module `apps/api/src/modules/uploads/routes.ts` must be tracked. The staged-file scanner makes the same distinction. Verify deploy source completeness by building an export of the Git index, not just the existing working directory; local files hidden by ignore rules can otherwise conceal missing repository modules.
